Audited on 2026-10-03 after reading all of `spec.md`. This report records the current sources and rebuilt images. The specification gives Phase 11 a review checklist rather than separate exit criteria; the gate remains §§36 and 45. No later phase or stretch feature was implemented.

## Findings fixed

1. **Requests could cross account boundaries after a delayed 401.** In an isolated browser, an authenticated `/auth/me` request was delayed, authentication was cleared, and a different account logged in. Releasing the old request's 401 caused the interceptor to refresh and retry with the new account, returning that account's data. This could also retry a write with a different actor. Requests now capture a session generation synchronously, before another operation can change accounts. A response from an earlier session cannot refresh, retry or clear the current session. Repeating the inspection returns the original 401, preserves the new account and performs no retry under it. A same-tick account-change inspection also confirms capture before the next microtask, rejection of the old request and preservation of the new account.
2. **Authentication cookie operations were incompletely coordinated.** Login could overlap a refresh response; logout stopped before contacting the backend when an existing refresh failed. Login/logout now wait for existing rotation to finish, prevent new background refreshes during the change, and ignore stale rotation results. Logout still runs after a failed pending refresh and rotates an expired access token once before retrying the protected logout endpoint. Successful login/logout update authentication and clear private query state inside their coordinated operation. Manual browser observations confirm that login waits, the new account survives another refresh, failed pending refresh does not skip logout, expired-access logout revokes the cookie, and a late refresh cannot restore cleared memory.
3. **The POM contained an unused test starter.** Removed `spring-boot-starter-test`; there is no test source tree or replacement testing dependency. Spring Boot remains exactly 3.4.3 and Java remains 21. The existing pinned Apache POI 5.4.0 was retained and verified with both actual exports.
4. **The current verification entry points needed the audit results.** README and the smoke checklist now link this audit and include account-change/late-response checks. The original report remains a dated implementation snapshot.

The session observations used temporary browser-side request delays and an isolated local profile. They are manual runtime inspections, not new application test files or dependencies. An initial observation against Vite hot-reloaded duplicate module instances did not exercise one shared client; it was discarded and repeated after restarting Vite. The recorded final observations use one client instance.

Final runs pass, including scoped permissions, duplicate applications, verified task/completion finality, stale versions and expense separation. - **Errors and validation:** actual HTTP checks return correlated JSON 400/401/403/404/405/406/409/415 envelopes with original paths.
